# ADR-008: Admin visual design — Affibloom's own design system

Status: **Decided** by the user
Date: 2026-11-12

## Context
Until now the plan rebuilt Lasso's admin in look as well as in function: Lasso's purple header, green buttons and
toggles, Helvetica Neue, its layout and measured sizes (`docs/ui/tokens.md`, ADR-7's "CSS kit using Lasso's
colours"). Tasks 8 (admin shell) and 9 (Settings → General) were built that way. The user decided that Affibloom
should have its own visual identity while staying identical in features and functionality.

Three scope questions were settled with the user on the same day:
1. **Scope: the admin only.** Every admin screen, modal, notice and the block's editor UI. The reader-facing product
   box keeps the site's current box design and its pixel comparison with Lasso's baselines (ADR-6), so guides do not
   change at cutover.
2. **Labels and workflow stay Lasso's.** Fields, labels, help texts, tab and column order and the steps of each
   workflow stay as `docs/spec/interface.md` gives them (the team knows them, and the acceptance tests use them). Only
   colours, typography, layout and styling become Affibloom's.
3. **A design task first.** The design system is proposed in `docs/ui/design-system.md` and approved by the user
   (plan Task 9A, before Task 10); Tasks 8 and 9 are then restyled to it.

## Decision
Affibloom's admin uses its own design system: colour palette, typography, spacing, layout and component styles
(header, tabs, cards, buttons, toggles, help tips, form fields, notices, tables, modals, counters). It meets WCAG 2.2
AA and is defined in `docs/ui/design-system.md`. Lasso's look is not copied; its brand marks never were.

## Why
The user's product decision: a distinct product identity, not a clone of Lasso's interface. Keeping Lasso's labels and
steps preserves what the team relies on (finding things where they expect them), so the change costs no retraining.

## Consequences
- ADR-7 still holds for how screens are built (PHP-rendered, small CSS kit, plain JavaScript), but its kit uses the
  Affibloom design system instead of Lasso's colours.
- `docs/ui/tokens.md` stays as a record of Lasso's measured admin values; it is no longer the source of admin styles.
- Admin screens are no longer compared with Lasso's screenshots for looks, only for fields, labels, help text and the
  order of steps. The box's visual tests are unchanged.
- The plan's CSS for admin components (phase files 2, 4, 6, 7) is superseded by the design system; class names and
  markup hooks stay, so tests and scripts do not change.
- Tasks 8 and 9 are restyled in Task 9A. The UI/UX improvements register (U1–U8) is about content and steps only.
